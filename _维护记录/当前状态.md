## 2026-09-27 · v0.3.0 第六轮：修浏览器崩溃 + 素材库真正可用 + 首次发版（等用户验收）

### 起因（用户报的两条）

1. 一打开卡片浏览器就弹 `TypeError: _browser_menu() missing 1 required positional argument: 'menu'`
   （`aqt\hooks.py` 第 1225 行），整个浏览窗口打不开。
2. 设置页「一键构建素材库」下载失败。

### 根因（都复现过，不是猜的）

1. **浏览器崩溃是插件自身 bug**：回调挂在 `browser_menus_did_init` 上，按 `(browser, menu)`
   两个参数写，但 Anki 26.09 这个钩子只传 `browser` 一个参数 → 参数不够直接抛错。
   修的过程中探针又挖出第二个真 bug：菜单加进去了又消失，是 **PyQt 生命周期**问题——
   局部 `QMenu` 的 Python 包装被回收，Qt 那边菜单跟着没。
2. **下载失败不是代码 bug**：下载地址指向的 `creeperboo/anki-exam-vocab-stats`
   仓库**在 GitHub 上不存在（404）**。音频包本体一直在本机
   `工具\素材构建\exam_materials_audio.zip`，sha256 与插件内置清单完全一致。

### 改了什么

1. **新增纯逻辑模块 `源码\hook_guard.py`**（不 import Anki，离线可测）：
   `bind_ok()` 用 `inspect.signature(...).bind()` 试参数；`guard()` 返回的包装器在参数对不上时
   只记日志并返回 `None`，参数吻合时正常调用并回传结果。**只拦签名不匹配，回调内部真异常照旧抛。**
   所有 `_add_hook()` 与 `profile_did_open` 注册统一走它。
2. **`_browser_menu` 改签名**为 `(browser, *args)`；菜单栏取 `browser.form.menubar`，
   退回 `browser.menuBar()`，都取不到就静默跳过。`QMenu` 给菜单栏当父对象 + 模块级
   `_BROWSER_MENUS` 留引用（只留最近 8 份），解决菜单被回收的问题。
   新增顶级菜单「应试词汇」（objectName `exam_vocab_stats_menu`），按 objectName 去重不叠加。
3. **`_deck_browser_menu(menu, deck_id)` / `_browser_context_menu(browser, menu)`**
   加参数换序自动对调 + 类型守卫（`_looks_like_menu` / `_looks_like_browser`）。
4. **素材库本地 zip 通道**：设置页新增「从本地 zip 文件安装…」（`install_materials_from_zip`），
   起始目录＝config `materials_zip` → `桌面\应试插件\工具\素材构建` → 桌面；
   后台算 sha256（与内置清单不符时再追问一次才继续），`resources.install_media(..., progress=)`
   带确定进度条解压，完成后写 `materials_zip` / `materials_installed_at` 并刷新状态行；
   `resources.install_media` 新增进度回调与返回文件数。
5. **下载通道加固**（`update_logic.py`）：新增 `MATERIALS_TIMEOUT=60` / `MATERIALS_RETRIES=3`、
   `download_to_file(..., resume=True)` 断点续传（重试带 `Range: bytes=<已下载>-` 续写同一临时文件，
   服务器回 200 则从头写，全失败清残留）、`materials_failure_text()` 明确告知可改用本地 zip。
6. **config**：新增 `materials_zip`；清理 v0.2 遗留的
   `custom_wordlists / dictionary_paths / audio_sources / network_materials / tts_fallback`。
7. `安装到Anki.py`、`工具\run_anki_probe.py` 的 `ADDON_FILES` 都加上 `hook_guard.py`；
   `manifest.json` 的 `mod` → `1791000001`（版本仍 `0.3.0`）。
8. 文档：`项目说明.md` / `操作指南.txt` / 源码 `README.md` / `config.md` /
   `设计方案.md` 补浏览器顶级菜单入口、钩子签名防护、素材库双通道，并澄清
   **Anki 26.09 已删除 `deck_browser_will_show_context_menu`**，牌组列表右键没有入口可挂，
   改由牌组齿轮/选项菜单承担。

## 2026-09-27 · v0.3.0 第五轮：发布通道修订 + 小瑕疵清理（等用户验收）

### 起因

准备首次建仓时踩到本机一键上传脚本的硬闸门：**单文件超过 5 MB 直接拒绝上传**
（`publish-to-github.ps1` 的 `$maxBytes = 5MB`，属脱敏闸门的一部分，不宜改）。
原设计要把 `exam_vocab_stats.ankiaddon`（12.5 MB）放仓库根目录当更新主通道，这会
**导致首次建仓直接失败**；`源码\data\ecdict_lite.json.gz`（7.3 MB）同样过不去。

### 改了什么

1. **分发包不进仓库，只挂 Release 附件。**
   `update_logic` 新增 `package_urls()`：分发包改成 **Release 优先、raw 兜底**
   （原来反过来）；`version.txt` 保持 raw 优先不变（只有 6 字节）。
   `fetch_package()` 改用它。
2. **`ecdict_lite.json.gz` 移出仓库和安装包。** 全项目搜索确认它只在构建期给
   `工具\构建素材库.py` 读，运行期读的是 `en_materials/ja_materials.json.gz`，
   留着等于每个用户白装 7.3 MB。`安装到Anki.py` 的 `ADDON_FILES`、
   `工具\run_anki_probe.py` 的期望清单同步删掉。
   分发包体积 **13,134,072 → 5,436,256 字节**。
3. **释义里的字面转义清理。** 英语素材有 66 个词条的释义带字面 `\n`（ECDICT 转义，
   落进卡片字段会原样显示成「\n」）。`resources.py` 新增 `_clean_text()`，`lookup()`
   吐出的音标/释义/例句/例句译统一还原；加 2 项测试钉住。
4. `.gitignore` 加两条排除；`manifest.json` 的 `mod` 1790800000 → 1791000000；
   设计稿与项目说明的发版流程改写（含 `gh release create` 完整命令与两个附件名）。

## 2026-09-27 · v0.3.0 第四轮：零漏识别 + 素材全内置 + 一键补漏（等用户验收）

### 这一轮做完的事

1. **识别：把「覆盖到了却没认出来」压到 0**
   - 英语并入 fushi 应用 `transforms/en.json` 的 **16 组去变形规则**（复数 s/es/ies/ves、
     所有格、过去式 ed/ied/双写、-ing 的 ying→ie、第三人称、比较级/最高级、-ly/-ily→y、
     -ly→le、-able/-ible、-ful/-less、-ness、-ment、-tion，un-/in-/im-/dis- 前缀），
     与原有 ECDICT 词元表、lemma 表、保守后缀串成一条链。
   - 短语与连字符归一：`make-up↔makeup`、`per cent↔percent`、`health care↔healthcare`、
     `post-war↔postwar`；词表里带空格/连字符的词（`t-shirt`、`co-operative`）保证原样命中。
     英美拼写补齐 `fulfil↔fulfill` 一类。

     修掉 eggrolls CSV `;` 并列写法解析（`キロ; キログラム`、`足; 脚` 共 27 行）；

   **A. 语言判定把「英文 + 中文释义」的牌库整块判成日语**
   - 症状：`English-CEFR` 被判成日语笔记类型 → 触发「疑似日语卡里的英文释义」规则 →
     英语轴唯一词变成 0，所有英文词表覆盖率 0.0%。
   - 原因：原实现把「纯汉字」也当日语票，中文释义数量远多于英文单词，投票压过去了。
   - 修法（`vocab_logic.classify_language`）：新增 `_RE_KANA / _RE_HAN / _RE_LATIN`，
     改成「只有假名才是可靠日语信号」：`假名 × 2 ≥ 拉丁` 才判日语，否则有拉丁字母就是英语。

   **B. `wordPartOfSpeech` / `SentType3` / `VocabPoS` 被当成取词字段**
   - 症状：`English-CEFR` 的取词字段选成了 `wordPartOfSpeech`（把正确的 `vocabularyWord` 挤掉）；
     `eggrolls-JLPT10k-v3.5` 选成了 `SentType3 / VocabPoS / VocabKanji / SentType2`。
   - 原因：ECDICT 里 `noun / verb / adverb` 本身就带 cet4 / cet6 / ky 标签，`SentType` 里的「対」
     本身就命中 JLPT 词表 —— 光看命中率拦不住（试过「只认考试标签」，`noun` 仍是 100%，已回退）。
   - 修法：新增 `vocab_logic.is_word_field_name()` 按字段名**一票否决**辅助字段
     （sentence / def / meaning / chinese / audio / phonetic / pos / partofspeech / grade / order /
     text / question / option … 以及中文的释义 / 词性 / 例句 / 音标 / 等级 / 备注 / 题目 等），
     `score_field` 对这类字段名扣 25 分；`analysis.detect_fields` 只从合格字段里选 `best`，
     没有合格字段就 `best=None`、不自动勾选（设置页仍显示它拿到的分数和预览，方便手动指定）。

   **C. 英美拼写对（fibre/fiber、colour/color、programme…）被当成「待确认」白丢覆盖**
   - 症状：待确认里出现 `program(program/programme)`、`fiber/fibre`、`humour/humor`、`litre/liter`、
     `realize/realise`、`endeavor/endeavour`。
   - 原因：`_pick` 里「标签数并列且内容不同 → 待确认」没有排除拼写变体。
   - 修法：新增 `_same_word_spelling()`（两词 ≥5 字母、长度差 ≤3、差异只允许在词尾 3 字母内），
     把并列拆成 `same_spelling`（标签取并集）与 `real_tie`（才进待确认）。
     `does → do` 这类真歧义仍走原逻辑，行为不变。
